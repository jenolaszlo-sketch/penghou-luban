# Penghou.Luban implementation audit — 2026-10-01

This audit records the implemented Windows read, capture, and narrow standalone
single-patch slices reviewed on 2026-10-01. It distinguishes executable
profiles from reviewed designs. The standalone exact-target patcher and
executor do not change capture-only behavior: `PreviewRuntime.WhatIfAsync`
has no writer callback or dispatch, and `ResolvedEffectPlan.CanCommit` remains
false.

## Completed and evidenced slices

1. **Shared Windows read provider and request identity.** Penghou owns the
   neutral I/O contracts, canonical request identity, and bounded
   `Penghou.IO.Local` reader. Luban's direct Read/Find/SearchText handlers use
   that provider while retaining required `IEffectAuthorizer` checks and their
   prior result shapes and recursive basename-pattern semantics. See
   [shared I/O integration](shared-io-integration.md), the provider
   [implementation plan](../../Penghou/docs/implementation-plan.md), and
   [Local reader profile](../../Penghou/docs/local-reader-profile.md).
2. **Minimal language and semantic IR.** The implemented language has a bounded
   parser/compiler, typed versioned IR, complete static preflight, and injected
   `ILanguageAuthorizer` checks at Preflight, EffectStart, ResourceAccess, and
   Release. Its operations are read, find, literal search, take, and count.
   Root-relative `*`, `?`, and whole-segment `**` globs are Unicode-scalar
   aware, ASCII-case-insensitive only, and distinct from legacy basename
   recursion. Broader syntax and transforms remain unimplemented. See the
   [read-language profile](read-language-profile.md) and
   [semantic IR](semantic-ir.md).
3. **Capture-only WhatIf.** The programmatic Local-only
   `PreviewCompiler`/`PreviewRuntime.WhatIfAsync` freezes an explicit authorized
   target view, admits every selected target before file-content reads, and
   captures bounded UTF-8 scalar-safe existing-file byte patches. All-match
   coverage and deferred Build/Test/GitCommit remain unresolved. The plan retains
   exact patch payloads and observation hashes, lengths and provider versions;
   it does not retain or expose full original/proposed file bytes. Unresolved
   earlier patch nodes block every later node because v1 has no virtual state;
   opaque effects retain their distinct dependency reason. `CaptureComplete`
   means capture finished only; `CanCommit` remains false. See the
   [capture profile](capture-preview-profile.md),
   [semantic preview identity](semantic-preview.md), and
   [ADR 0004](decisions/0004-preview-resolution-commit-barrier.md).
4. **Narrow standalone Local patch execution.** The exact-target
   `SinglePatchExecutor` and Local Windows NTFS patcher accept one complete
   existing-file byte patch through a required host admission, current resource
   checks, serialized start fence, and outcome journal. This is a separate
   profile; it does not enable WhatIf dispatch, broad batch execution, Hufu or
   Zhinu integration, or atomic-transaction claims. The profile documents its
   byte/read/work bounds, exact version checks, in-place write behavior, and
   ambiguous post-start outcomes. See [single-patch execution](single-patch-execution-profile.md).

The implementation plan and roadmap record milestones 1–5 as implemented. The
fresh full Luban suite passed 145 tests on each of .NET 8 and .NET 10 with no
skips, including the current writer, authorization-budget/release fixes, and
17 or more executor-focused cases. The shared native-profile suite passed 81 tests on each framework with no skips, limited to the explicitly HostControlled NTFS namespace. Executed locally during this audit; these results do not requalify other platforms or production adapters.

## Review findings and corrected test assumptions

- The qualified glob grammar intentionally caps patterns at 256 UTF-16 code
  units. Adversarial matching tests must use accepted patterns within that cap;
  a separate test verifies rejection above the cap.
- A `**` segment can consume zero or multiple segments. In particular,
  `src/**/x.cs` can still descend from `src/a/x.cs`, because the globstar may
  consume the current `x.cs` and the trailing `x.cs` may match a child. A test
  expecting that directory to be impossible would be incorrect; the current
  tests capture the viable-prefix behavior.
- Runtime language preflight now charges authorization calls from every phase,
  including `Preflight`, against `MaxResourceCalls`. A regression case with two
  known nodes and a budget of one denies before any protected target I/O; the
  earlier accounting omitted preflight calls from the budget.
- Path continuation binds normalized path identity with ordinal comparison
  after ASCII-only case folding. It deliberately does not use broad Unicode
  case-insensitive comparison: e.g. `cafÉ` and `café` are different cursor
  bindings even on a filesystem whose comparison may equate them. This is about
  the path binding; cursor tokens remain random, single-use and context-bound,
  without an ASCII-only token restriction.
- Capture selection is not a live directory snapshot, and provider content
  hashes/versions do not prove a future pathname still identifies the same file
  object. The existing Local reader is path-based and explicitly does not claim
  confinement against concurrent path replacement, hard-link alias detection,
  or mount-boundary protection.
- Earlier patch nodes with unresolved capture or coverage conservatively block
  every later node with `DependsOnUnresolvedEffect`; v1 has no virtual workspace
  state to model their possible effects. Opaque effects retain their separate
  dependency reason. This prevents later captures from treating the unchanged
  workspace as if an earlier mutation had succeeded.
- Codec decoding enforces the 16 MiB envelope and rejects patch counts above
  4096 before copying patch payloads. The single-patch writer applies the
  stricter limit of 128 edits. The runtime's conservative preview call lower
  bound is seven calls plus two per directory segment, not a claimed
  worst-case bound for all nodes.
- CedarSharp's managed malformed-surrogate `TryParse` failure was corrected and
  its native-backed assertion executable reported 34/34 passing tests on each
  of .NET 8 and .NET 10. This local regression fix does not itself expand the
  package's published release qualification; the CedarSharp verification record
  remains authoritative for release claims.

## Remaining gates and risks

This records the earlier single-file audit. Subsequent work implements the narrow
[batch execution and recovery profile](batch-execution-profile.md); its separate
qualification record supersedes the batch-pending status below.

The next work is broader writer consistency and admission: qualified
multi-target/batch admission, additional resource-start fencing contracts,
recovery semantics, and production Hufu/Zhinu adapters. The standalone patcher
performs an in-place write and is not crash-atomic. Its pinned directory handles
and exclusive target handle constrain ordinary concurrent opens but do not
protect against privileged actors or raw-volume modification. The original
preview version is a content precondition; it does not promise that a later
pathname denotes the original captured file object. Do not automatically retry
an ambiguous post-start result. Qualification and host evidence must establish
which operations are definitely not started versus started/uncertain and how a
host reconciles them.

Useful follow-up opportunities include inspectable redacted diagnostics that
identify the node and authorization phase, explicit host-visible distinctions
between definite no-mutation and started/uncertain outcomes, and a release-time
recheck whenever a host renders plan or preview details. These are not claims
that current rendering implements those controls; adapters remain responsible
for protecting sensitive evidence and checking current authority.

The broader source surface, mutation syntax, ranges, richer search, directory
metadata, copy/move/delete/create, web, Git, and native developer tools remain
outside the completed read profile. Consumer operators remain buffered and
bounded; lazy streaming and backpressure are not guaranteed.
